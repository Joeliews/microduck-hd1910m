# 持续目标与自动推进

源文件 `/workspace/microduck-closed-loop/standing-goals.md` 在本环境读不到。下面按给定条款写入，不改规则，也不改已有短评估的结论。

## 持续目标

在可追溯参数假设范围内通过完整仿真闭环验收。XL330 与 HD-1910 分别覆盖官方 10 个策略。范围包括：官方动力学、多种子与独立测试种子、必要的 PPO 重训、actor 与 ONNX 的数值对照，以及 Rust 控制核心接入 MuJoCo 后的 50 Hz 验证。实物仍锁定。

HD-1910 缺测不得凭空补齐。只能在可追溯估计与随机化范围内做「条件仿真验收」，并与实测校准及实机验收分开。

## 自动推进

自主规划，然后在现有项目、现有 PR 里用 Cursor 编码，再在本机隔离环境执行，接着做独立证据审查。失败则返工，然后自动进入下一项。不等用户说继续，也不在只写计划后停止。

同一失败连续两轮没有新证据，就暂停该项，并保留日志、原因和需要的外部输入，继续其他不依赖该项的工作。禁止绕过检查或降低标准。

## 约束

不重复建项目。串行使用本机 GPU，检查点可恢复。不租付费 GPU，不购买服务，不改全局安全设置，不终止其他项目进程，不连实物，不合并 main，不发布。

云端与本机之间留可重放的交接工件。不得声称本机私有 Cursor worker 已接通。

## 本机短训

隔离的本机环境可以做 PPO 仿真训练。「不要在云端开 6000 轮」不是禁止必要的重训。规则是：先短训，再按评估决定是否加长；检查点可恢复；串行占用本机 GPU；不购买服务。云端不启动 6000 轮。短训导出不得覆盖官方权重的行为格或零样本格。
