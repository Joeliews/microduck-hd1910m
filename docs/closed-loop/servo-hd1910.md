# HD-1910 参数冻结与待实测

HD-1910 没有本机实测辨识。下面每一项都标了来源。规格书上的数可以拿来做带假设的仿真，仿真结果不能写成实测。PPO 在线采样不会把缺的辨识项补上。

本 Fork 现有 JSON 的 `actuator` 字段是 `sts3215`。只改名字不会变成 HD-1910 辨识。

## 身份

| 名称 | 指什么 | 标记 |
| --- | --- | --- |
| HD-1910-C001 / HD1910M | 飞特规格书型号。产品名写「HD1910M, 6V 12kg TTL 塑胶壳空心杯金属齿 360 度磁编码双轴」 | 规格 |
| STS3215 | 另一款舵机：约 45.2 × 24.7 × 35 mm，约 55 g，7.4 V 堵转 19.5 kg·cm，减速比 1/345，有刷电机 | 规格。不是 HD-1910 |
| 本仓库 `hd1910_1910_m6.json`、`radxa_1910_m6.json` | 文件名像 HD1910，内部 `"actuator": "sts3215"`、`"model": "m6"` | 仓库文件自标。不能当作 HD 辨识 |

`THIRD_PARTY.md` 把 M6 参数记为 `LuwuDynamics/xgoduck_rl` 的外部参考，并写明不等于本机已完成执行器辨识。

测试 `microduck_rl/tests/test_hd1910_bam.py` 还断言这份参数 `actuator == 'sts3215'`。改断言里的字符串而不改测量，不算辨识完成。

## 几何

`robot_description/` 与 RL 树里的网格、URDF 是 CAD/装配几何，标记为 CAD。它们给出连杆形状，不给出舵机扭矩-速度曲线、惯量或摩擦。

## 缺失，待实测

下列项没有本机数据。规格书有的，已在上表标成规格，这里只列规格仍不够、或规格与仿真参数对不上的部分。

| 项 | 为什么缺 |
| --- | --- |
| 扭矩-速度曲线 | 规格只有堵转点和额定点，没有曲线，也没有这批舵机的实测点 |
| 电流 / 限流在本机电源下的实际值 | 规格有堵转和额定电流；总线压降、电源内阻、固件限流没有测 |
| 响应延迟 | JSON 里的 `command_delay` 属于自标 `sts3215` 的文件，不是这批 HD-1910 的阶跃测量 |
| 摩擦（库仑、Stribeck、粘性、负载相关） | 只有那份 `sts3215` JSON。规格书没有这些系数 |
| 齿隙的实测分布 | 规格 ≤ 0.5° 是上限，不是这 15 只的测量 |
| 质量与转动惯量 | 规格重量 21 ± 2 g 是整机质量。输出轴惯量、电枢惯量没有测。CAD 质量若未称重，仍是估计 |
| 绕组电阻、扭矩常数的实测 | 规格 Kt 是 7.5 kg·cm/A。JSON 的 kt、R 是另一套自标 `sts3215` 的数 |
| 温度、电压跌落 | 没有 |
| 与 XL330 策略 HOME 的编码器零位差 | 部署零位在每台机器的标定文件里，不是 BAM `q_offset` |

## 若要仿真，假设要写在旁边

可以用规格书的堵转扭矩、额定电流和 ±10% 公差做先验，随机化范围先取规格已经写明的 ±10%，摩擦和延迟在有实测之前用更宽的范围并标成估计。这样跑出来的轨迹是「规格先验下的仿真」。它不填上表，也不能把 PPO 采样到的参数回写成辨识结果。

HD-1910 的 10 个策略格全部未执行。见 `policy-matrix-20.md`。
